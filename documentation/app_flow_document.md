# App Flow Document for SA:MP Roleplay Forum

## Onboarding and Sign-In/Sign-Up

When a new user first arrives, they see a simple landing page that introduces the forum and offers buttons to sign in or sign up. By clicking the sign-up link, the user is taken to a registration form where they enter their email, choose a username, and create a password. Once these details are submitted, the system sends a confirmation email and, after confirmation, logs the user in automatically. If a user has already registered, they click the sign-in link, which brings up a login form requesting email and password. Submitted credentials are checked against the server and, when valid, a secure cookie is set and the user is redirected to their dashboard. If the user forgets their password, they follow a “Forgot Password” link that prompts them to enter their email. An email with a reset link arrives in their inbox, and clicking it takes them to a page where they can create a new password. After resetting, they can sign in as usual. Signing out is always available via a link in the header or sidebar, which clears the session cookie and returns the user to the landing page.

## Main Dashboard or Home Page

After signing in, the user lands on the main dashboard. At the top is a header showing the forum logo, the user’s avatar, and quick links for notifications and settings. Along the left side is a navigation bar that always shows links to the main forum, the user’s profile area, and the admin panel if they have moderator or administrator rights. The center of the dashboard greets the user with recent activity in threads they follow, a summary of unread messages, and a small widget showing current SA:MP server status such as online player count. From here, the user can click the forum link to jump into the full list of categories or choose the profile link to view or edit personal details.

## Detailed Feature Flows and Page Transitions

When a user clicks the forum link from the dashboard, they arrive at the category list page. This page displays every forum category like General Discussion, Roleplay Stories, and Server News. Clicking on a category name loads the thread list for that category. Each thread entry shows its title, the name of the author, and the date of the last reply. If the user wants to start a new conversation, they click a “Create New Thread” button that opens a page where they fill in the thread title, optionally select an image to upload, and write a message using the built-in Markdown editor. Submitting this form sends a request to the server and then redirects them directly to their new thread page.

On a thread page, the original post appears at the top, followed by all replies in chronological order. At the bottom of the thread, the user sees a reply box with the same Markdown editor. They type their reply, optionally add images, and submit. The thread page refreshes to show their new post immediately. If the user has permission, they will see edit and delete icons next to their own posts; clicking an edit icon transforms the post back into an editable Markdown form to update content.

Moderators and administrators access special tools through the admin panel link in the sidebar. That panel displays reports of problematic content, user ban controls, and server-side logs. When an admin clicks on a reported post, they land on a review page where they can choose to delete the post, warn the user, or impose a temporary ban. Banning a user opens a simple form to define ban duration and reason, then updates the user’s status in the database.

Real-time notifications pop in from the corner whenever someone mentions the user or replies to a watched thread. These notifications use a WebSocket connection set up by Socket.IO, and clicking a notification brings the user to the relevant post or thread page.

Special pages under `/api/samp` feed live game data into the forum. For example, the user can click a “Server Stats” link to view a component that shows current faction leaderboards and top players. This data is fetched on the server and rendered without any loading spinner on the client.

## Settings and Account Management

From the dashboard header or sidebar, the user clicks their avatar to enter account settings. This page is divided into sections for profile details, avatar image, and notification preferences. In the profile section, they can update their display name and email address. In the avatar section, they upload a new picture, which is sent to a cloud storage service and then displayed immediately. Under notification preferences, they toggle email alerts or real-time pop-ups for mentions and private messages. All changes are saved with a clear “Save Changes” button that, when clicked, confirms the update and returns them to the settings page. A link at the bottom of the settings page logs the user out and takes them back to the landing page.

## Error States and Alternate Paths

If the user enters an incorrect password or email on the sign-in form, an inline message informs them of invalid credentials without reloading the page. On the sign-up form, missing or incorrect fields trigger highlighted errors explaining what needs fixing. Should the user navigate to a non-existent category or thread, they see a friendly 404 page offering a link back to the home page. If a user without moderator rights tries to visit the admin panel URL directly, they get an “Access Denied” page with a link back to the dashboard. During network outages or slow connections, a banner appears at the top of any page warning of offline status, and actions like posting or saving show queued states until the connection returns.

## Conclusion and Overall App Journey

In a typical journey, the user arrives at the forum landing page, signs up or logs in, and lands on their dashboard where they can preview recent activity and the current server status. From there they enter the forum, browse categories, read threads, and create new discussions. They reply to posts, receive real-time notifications of mentions, and adjust their profile details or notification settings at any time. Moderators and administrators follow the same path until they use special admin tools to manage reports and enforce bans. Throughout, theme toggles let the user switch between light and dark modes. Finally, when the user is done, they log out to end their session, ready to return and pick up where they left off.
